# 자동 화면 투어와 자동 검사

주인님이 직접 플레이하지 않고 사진과 숫자로 판단하실 수 있게, 정해진 장면을 밤과 아침으로 찍고 주인님 지적 항목을 숫자로 재서 통과, 실패 표를 만든다.

## 파일
- serve.py: game 폴더를 http://localhost:8777/ 로 보여 주고, 사진과 결과를 runs/<판 이름>/ 에 저장하고, 앞 판과 나란히 놓은 index.html을 만든다. 게임 주소(8765)와 주소가 달라 브라우저 저장소가 따로라 이어하기 저장을 건드리지 않는다.
- dd_check.js: 게임 페이지에 읽혀 쓰는 투어와 검사(DDC). 탭 안에서는 저장을 막고(localStorage, saveGame) 소리를 끈다. 창이 가려져 있어도 되게 게임 프레임을 손으로 돌린다.
- runs/<판 이름>/: 사진(장면_night.jpg, 장면_day.jpg), shots.json, checks.json, index.html(앞 판과 비교 페이지). 저장소에는 넣지 않는다(.gitignore).
- 첫 판(기준): runs/2026-11-27_base/index.html

## 돌리는 법
1. game 폴더에서 서버를 띄운다.
   python tools/check/serve.py
2. 브라우저(앱 안 브라우저 탭)로 http://localhost:8777/index.html 을 열고 콘솔에서 읽는다.
   await new Promise(r=>{const s=document.createElement('script');s.src='/tools/check/dd_check.js?'+Date.now();s.onload=r;document.head.appendChild(s);});
3. 한 번에: await DDC.all('2026-11-28_1')   (판 이름은 영문, 숫자, _, - 만)
   - 오래 걸리는 한 번의 실행이 도구 시간 제한(45초)에 걸리면 나눠서 돌린다:
     DDC.run='2026-11-28_1'; await DDC.tour(['title_16x9','title_4x3','title_phone','newgame']); await DDC.tour(['cap_yard','cap_stair','door_front','door_cross','palace_in']); ... (장면 이름은 DDC.SCENES)
   - 검사는 왕궁에서: 전투 장면 전에 await DDC.checks() 또는 DDC.ck.<이름>() 하나씩(shield, walk, collide, ride, people, door, sword, camwall, overlap). 전투 검사는 전투 장면을 돌릴 때 함께 잰다.
   - 글씨, 단추 겹침은 지금 창 크기에서 잰다. 앱 브라우저 창 크기를 1280x720, 812x375로 바꿔 DDC.ck.overlap('PC'), DDC.ck.overlap('휴대폰 가로')를 각각 부른다.
   - 끝: await DDC.finish() (콘솔 오류 항목을 더하고 checks.json 저장, 비교 페이지 만들기)
4. 영어판: http://localhost:8777/en.html 을 열고 같은 방법으로 읽은 뒤 DDC.run='같은 판 이름'; await DDC.tourEn(); 그다음 다시 await DDC.post('done','') 로 비교 페이지를 다시 만든다. (en.html은 tools/i18n/gen.py로 새로 만들어야 index.html의 최근 변경이 들어간다)
5. 결과: http://localhost:8777/tools/check/runs/<판 이름>/index.html (왼쪽 앞 판, 오른쪽 이번 판, 위에 검사 표와 앞 판 결과)
6. 끝나면 탭을 닫고 서버를 끈다.

## 투어 장면 (밤 S.t 0.95, 아침 0.33)
처음 화면 16:9, 4:3, 휴대폰 가로 / 왕궁 마당 / 신전 계단 위 돌기둥 / 대전 문 앞(문 열림, 문 너머 대전) / 대전 문을 막 넘은 순간 / 대전 안(왕좌 쪽, 문 쪽) / 말 탄 왕(옆, 뒤) / 걷는 왕(왼쪽 뒤) / 시장 / 정문 / 지도(왕도, 도시 두 곳, 망자의 왕좌) / 도시 화면 / 도시 방어전 / 왕궁 방어전 성벽 0~3단계 / 프롤로그 전투 / 망자의 왕좌 전투 / 영어판 처음 화면과 왕궁.
- 사진은 3D 화면만 찍힌다(글씨, 단추 없음). 글씨 겹침은 검사 표로 본다.
- 새 판(1일째)에서 찍으므로 지도의 정찰 안 한 곳(왕좌 등)은 구름에 덮여 있다.

## 검사 항목과 기준
- 방패가 망토 뒤로 넘어감: 걷기, 달리기 동안 엉덩이보다 12cm 넘게 뒤(망토 쪽)로 간 방패 점 0개 (팀원 6 king_probe.js KP.behind, 점은 무게로 고름)
- 걷기 배속, 발 미끄러짐: 배속 0.7~1.4, 땅에 디딘 발(1/120초 간격, 가장 낮은 높이에서 1.5cm 안)의 미끄러짐 가운데값 0.6m/s 아래
- 왕이 기둥, 나무, 건물을 뚫음: 계단 기둥, 성 안 나무, 건물 둘레에서 안쪽으로 걸어 들어가(걷기, 말) 몸 반지름 안에 막힌 칸이 남거나 건물 상자 속에 들어간 횟수 0
- 화면 글씨, 단추 겹침: 대장간 앞, 대전 문 앞, 왕궁 마당에서 화면 위 상자(absolute, fixed)끼리 4x4픽셀 넘게 겹치는 곳 0
- 말 위 높이: 왕(서기, 속보, 질주), 기병 군중의 엉덩이와 말 등 틈 -5~5cm (KP.gapRide2, KP.crowdGap). 선왕, 지도 모형은 투어 사진으로 본다
- 왕궁 사람 키: 군중 모델 서 있는 자세 키 1.5m 넘게
- 대전 문: 걸어서 드나드는 동안 상호작용 단추 뜬 프레임 0, 카메라 한 프레임 이동 0.6m 아래
- 칼이 말 몸을 뚫음: 말 위 서기, 질주, 베기 동안 말 몸 속 칼 점 0 (KP.swordIn)
- 카메라가 건물 벽 속: 건물 둘레에서 카메라 8방향, 벽 속 0번
- 전투(투어 전투 장면마다): 성벽 위로 그려지는 병사 중 발 둘레 다섯 곳 아래 1.6m 안에 아무 모양도 없는 허공 병사, 땅 위 병사가 성벽 두께 속(무너지지 않은 칸), 도시 방어전 집 상자 속 병사. 모두 0명
- 백성이 왕, 말 몸 속에 든 횟수: 왕이 가는 길에 백성 여덟을 세워 두고 걷기, 말 타기로 3초씩 지나갈 때 0번. 대전 신하, 경비 쪽으로 걸어 들어갈 때 왕과 가장 가까운 거리 0.7m 넘게
- 콘솔 오류(한국어판, 영어판): 0건

## 알아 둘 것
- 전투는 빛(낮, 밤)을 싸움 시작 때 한 번만 정한다. 투어는 시각을 바꾼 뒤 dayNight(BR.lights...)를 다시 불러 맞춘다.
- 전투 장면은 시작 뒤 약 7초(200프레임) 지나 찍고 잰다(성벽 모델, 성벽 위 디딜 곳 표가 갖춰진 뒤).
